# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A 2D platformer built with **Godot Engine 4.7** (Standard build — no C#/.NET), using the Pixel Adventure 1 art pack. Player picks a character, dodges hazards (spikes, saws, patrolling enemies), collects fruit, hits checkpoints, reaches the goal flag. UI, README and CONTRIBUTING are written in Vietnamese.

## Project layout gotcha

The Godot project root is **`game/`**, not the repo root. Import `game/project.godot` in Godot. The repo root holds only docs plus loose asset archives (`*.zip`, `*.rar`, extracted pack folders like `adve/`, `Kings and Pigs/`, `Free Smoke Fx Pixel 2/`) that are raw source art, not wired into the project — leave them alone unless a task is about importing new assets.

## Running / testing

- No CLI build or automated tests. Open `game/project.godot` in the Godot 4.7 editor and press F5. Main scene is `res://ui/main_menu/main_menu.tscn`.
- `godot` is not on PATH in this environment; you cannot run the game headless here. Reason about `.gd`/`.tscn` files directly and describe what to verify in-editor.
- After any folder-structure change, CONTRIBUTING requires opening the project in the editor once so it rescans and re-saves scenes flagged dirty.

## Architecture

**Feature-based folders, not type-based.** Each feature folder (`player/`, `levels/level_N/`, `objects/<thing>/`, `ui/<screen>/`) contains its own `.tscn` + `.gd` + `sprites/`. Only put an asset in `game/shared/` or `game/ui/shared/` if ≥2 features actually reference it (grep the path in `*.tscn`/`*.gd` to confirm).

**Autoloads (`game/core/`, registered in `project.godot [autoload]`):**
- `Events` (`events.gd`) — global signal-bus autoload: **signals only, no state or logic**. Gameplay `emit`s; HUD / SaveManager / achievements `connect`. Keeps gameplay decoupled from UI/Save. Not yet wired (skeleton from ROADMAP Phase 0).
- `GameManager` (`game_manager.gd`) — **pure runtime** state that survives scene changes: `selected_character`, `current_level_id`, `score`, `respawn_position`/`has_checkpoint`, `last_result` (`"win"`/`"lose"`), `_elapsed` playtime (paused-aware). `start_new_run()` resets it + calls `SaveManager.set_last_level()`. Hearts live in the player's `HealthComponent`; HUD reads them via `Events.player_health_changed`.
- `SceneTransition` (`scene_transition.tscn`) — **always** change scenes via `SceneTransition.goto(path)`. It unpauses, plays the fade animation, swaps the scene, never leaves the tree paused.
- `SaveManager` (`save_manager.gd`) — persists `completed_levels`, `high_scores`, `best_times`, `settings`, `unlocked_abilities`, `defeated_bosses`, `collected_secrets`, `max_hp_bonus`, `last_level` to `user://save_data.json` as JSON (every load is `.get(key, default)` for forward/backward compat). `is_level_unlocked()` gates level N on N-1. `record_result()` from the end screen. `get_setting`/`set_setting` for prefs. `is_ability_unlocked`/`unlock_ability`/`get_unlocked_abilities`, `is_boss_defeated`/`mark_boss_defeated`, `is_secret_collected`/`collect_secret`, `get_max_hp_bonus`/`add_max_hp_bonus`, `get_continue_level`/`set_last_level` — gameplay/UI query only through these, never the file.

**`AbilityGate`** (`objects/ability_gate/`) — `StaticBody2D` on the `world` layer that blocks passage until `SaveManager.is_ability_unlocked(required_ability)` (checked on `_ready` + `Events.ability_unlocked`); opens permanently. The metroidvania primitive. **`objects/secret_alcove/`** bundles one (`required_ability="dash"`) mid-way across a small floating `StaticBody2D` platform — you can land on the near half without dash but the gate walls off the far half where a **`objects/collectible_diamond/`** sits. Diamonds (`@tool` Area2D like `fruit.gd` but persistent — `@export secret_id`, `queue_free`s on `_ready` if `SaveManager.is_secret_collected`, else on pickup calls `collect_secret` + emits `Events.collectible_collected(id, "diamond")`) are placed under a `Secrets` node in each Forest level (`diamond_forest_1..3`). Collect all 3 → heart container (see `Progression`).
- `Progression` (`progression.gd`) — progression rules autoload: on `Events.boss_defeated` it `SaveManager.mark_boss_defeated()` and, if `BOSS_REWARDS` has the boss, `unlock_ability()` + emits `Events.ability_unlocked`. On `Events.collectible_collected` for a `"diamond"`, once all of `FOREST_SECRETS` (the 3 forest diamond ids) are in `collected_secrets` and no bonus yet, `SaveManager.add_max_hp_bonus(1)` + emits `Events.max_hp_increased(new_max)`.
- `Toast` (`toast.tscn`) — autoload CanvasLayer; on `Events.ability_unlocked` (etc.) slides a short message in at top-center. Survives scene changes.
- `Dialogue` (`ui/dialogue/dialogue.tscn`) — autoload CanvasLayer; `Dialogue.open(lines: PackedStringArray, speaker := "")` shows a bottom text panel, `interact`/`jump` advances a line, `set_input_as_handled()` so the same press doesn't leak to the player/portal. `is_open` flag (every `interact`-polling node — portal, hub_sign, npc — must gate on it) stays true one extra frame after the closing press. Not modal (no `get_tree().paused`). Emits `finished`.

**Non-autoload global classes (`class_name`):**
- `LevelData` (`core/levels.gd`) — the ordered `LEVELS` array (id / name / scene path) is the single source of truth for level order and the linear unlock chain (`SaveManager.is_level_unlocked` gates level N on N‑1). Order **matches `WorldData.WORLDS`**: `level_1, level_2` (forest), `level_3, level_4, boss_forest` (castle), `level_5, level_6, boss_dungeon` (dungeon) — so the two never disagree. Add a level = add one entry here + update `WorldData.WORLDS`. Also holds `format_time()`.
- `CharacterData` (`core/characters.gd`) — playable roster: `NAMES` (order shown in `character_select`) + `CHARACTERS` dict (display name, per-character `sprite.offset` to align feet to the shared collision box) + path helpers for `<name>_frames.tres` / `portrait.png` in `player/sprites/<Name>/`. Roster is King + Captain (Pixel Frog CC0, have attack anims); the 4 old froggy chars (`player/sprites/Ninja Frog/` etc.) are retired from `NAMES` but their folders stay for future skins. `character_select` builds its buttons from `NAMES` in code (like `level_select`).

**Reusable components (`game/components/`, `class_name`)** — 1 job per node, attached in the scene, wired via `@export`. `HealthComponent` (Node) — hp + i-frames; pure logic, emits `died`/`health_changed`/`invincibility_started`; owner forwards to `Events`. `Hitbox` (Area2D) — deals damage, passive data holder (`damage`, `knockback_force`), `enable()`/`disable()` per attack frame. `Hurtbox` (Area2D) — receives damage, active: on `area_entered` reads `damage` from a `Hitbox` (or 1 from a plain hazard Area2D on its mask layer) → `health_component.damage()`, emits `hurt(source)`. `EnemyHitReaction` (Node) — drop next to a `HealthComponent`; flashes the sprite white on `damaged`, and on `died` freezes the enemy, disables its shapes, emits `Events.enemy_died`, plays a pop tween, then `queue_free`s. All four auto-find a sibling `HealthComponent`/`AnimatedSprite2D` if the `@export` is unset. See CONTRIBUTING.md for the collision-layer table.

**Player (`player/player.gd`)** — `CharacterBody2D`, in group `"player"`. Hand-rolled movement: gravity, double jump (`MAX_JUMPS`), wall slide + wall jump. Infinite wall-climb is blocked two ways: a short post-jump horizontal input lock (`WALL_JUMP_LOCK_DURATION`), plus `last_wall_jump_dir` — you can't wall-jump the same wall face twice until you touch the floor or the opposite wall (zig-zag between two walls still works). Health lives in a `HealthComponent` child (`$HealthComponent`, `max_hp` 3, + `SaveManager.get_max_hp_bonus()` from heart containers applied in `_ready`; also listens to `Events.max_hp_increased` to bump live); `player.gd` connects its signals — `hit(force_reposition)` calls `health.damage(1)`, `died` → `_on_health_died` (respawn at checkpoint if any, else end screen), `health_changed` → mirrors `GameManager.hearts` + emits `Events.player_health_changed`. Player also listens to `Events.checkpoint_activated` to heal to full. `win()` sets result and transitions. Player scene has a `Hurtbox` child (mask `enemy_hitbox`) — `player.gd` connects `hurtbox.hurt` → `_on_hurt` (plays "hit"); damage is applied by the Hurtbox itself. Attack: `attack` action → `_start_attack()` places the `Hitbox` child in front by `facing` × `CharacterData.get_attack_reach()`, plays the `"attack"` anim; `sprite.frame_changed` enables the Hitbox from frame 1, `animation_finished` disables it and clears `is_attacking`. `hitbox.hit_landed` → brief `Engine.time_scale` hit-stop (`SceneTransition.goto` resets `time_scale` as a safety net). **Dash** — `dash` action, gated by `$AbilitySystem` (`ability_system.gd`, `is_unlocked("dash")` via `SaveManager`, `dev_unlock_all` export for testing); when `is_dashing`, `_physics_process` sets a flat horizontal velocity, skips gravity, and returns early. Cancelled by `_end_attack()` (called on hurt/death/respawn). Spawns `objects/fx/dust.tscn`. Only Dash goes through `AbilitySystem`; double/wall jump stay inline.

**World themes (Phase 9)** — each of the 3 worlds has its own **terrain tileset** (all 16px so player physics are identical): forest = `levels/level_1/terrain_tileset.tres` (grass); castle = `levels/shared/tilesets/castle_terrain.tres` (`castle_stone_16.png`, Kings-and-Pigs 32px downscaled); dungeon = `levels/shared/tilesets/dungeon_terrain.tres` (`dungeon_stone_16.png`, GothicVania Cemetery tileset recoloured). Each `.tres` = one `TileSetAtlasSource`, a full-square `physics_layer_0` polygon per used tile, `physics_layer_0/collision_layer=1`, NO `terrain_set` (autotiling is done by the scratchpad `levelkit.py` build tool, not Godot terrains). Backdrops are **`Parallax2D`** scenes (`shared/backgrounds/{forest,castle,dungeon}_parallax.tscn`, `scroll_scale (0.3,0.55)`, one big 2400×1600 `*_backdrop.png` child) — NOT `CanvasLayer` (that was screen-pinned). Level scenes are generated by `scratchpad/levelkit.py` (`tile_map_data` + object placement); the flat `build_level_N.py` per-level scripts + `gameview.py` WYSIWYG preview renderer are in the session scratchpad, NOT committed. `camera_limit_bottom` must be ≥ `player_y + ~190` (view half-height at zoom 1.7) or the player jams against the bottom edge; terrain fill must extend past it.

**Levels** — all five level scenes (`levels/level_1`..`level_5`), the boss arena, and the hub share the single script `levels/level_base.gd` (`class_name LevelBase`; boss arena and hub `extends LevelBase` with a thin override). It sets the spawn point from `$Interactables/StartMarker` in `_enter_tree()` (before children `_ready()`), refills hearts, applies exported camera limits, detects falling off the map (`fall_death_y`), and owns the pause menu. Per-level scene tree convention: group nodes under `Interactables` (StartMarker, GoalFlag, Checkpoint), `Enemies`, `Fruits`.

**Boss** — `BossBase` (`objects/bosses/boss_base.gd`, `class_name`, `CharacterBody2D`, groups `"enemy"`+`"boss"`): its own FSM (`INTRO`/`THINK`/`ATTACK`/`RECOVER`/`HURT`/`DEAD`), no coroutines — patterns are timer/step driven. Reuses `HealthComponent`/`Hurtbox`/`Hitbox` + `EnemyStats`; forwards HP → `Events.boss_health_changed`, phase → `Events.boss_phase_changed`, death → `Events.boss_defeated(boss_id)`. **King Pig** (`objects/bosses/king_pig/king_pig.tscn`, hp 10) — patterns unlock by phase (`_check_phase` at ≤66% / ≤33% hp): `bomb_toss` always (spawns an `objects/bomb/bomb.tscn` `Bomb` that arcs to the player, flight time scaled by distance, only the explosion hurts); `charge` from phase 2 (telegraph → dash, `Hitbox` on, long stun on wall hit); `jump_slam` from phase 3 (`SlamHitbox` = wide flat shockwave on landing). Phase change = roar + ~1s i-frame. `BodyHitbox` = always-on contact damage. `arena_bounds` (set on the instance) clamps the boss inside the room during charge. Arena `levels/boss_forest/boss_forest.tscn` (`boss_arena.gd extends LevelBase`, no goal flag — win on `boss_defeated`; `objects/boss_gate/` closes it, opens on defeat); registered as `boss_forest` in `LevelData`, unlocked after level 5. `ui/boss_health_bar/` listens to the `Events` boss signals.

**Enemies** — `EnemyBase` (`objects/enemies/enemy_base.gd`, `class_name`, `CharacterBody2D`, group `"enemy"`): hand-rolled FSM (`PATROL`/`IDLE`/`CHASE`/`ATTACK`/`RETURN`/`HURT`), gravity, a `FloorCheck` `RayCast2D` to turn at ledges. Tuning comes from an `EnemyStats` resource (`@export stats`); HP from a `HealthComponent` child; damage/death/flash reuse `Hitbox`/`Hurtbox`/`EnemyHitReaction`. `behavior` = `PATROL` (walk a range, chase on sight) or `GUARD` (hold position, lunge, return). `sprite_faces_right` handles sprite default orientation (Kings & Pigs sprites face left). The **Pig** (`objects/enemies/pig/pig.tscn` + `pig_ambusher.tscn`) is the only enemy type; it replaced walker/spike_head/chaser_spike. `flyer` is still a standalone `Area2D` flying hazard (not on `EnemyBase`).

**Traps & interactables (`objects/`)** — `spikes`/`saw`/`orbit_saw`/`falling_spike` are `Area2D` on the `enemy_hitbox` layer, no damage script (the player's `Hurtbox` detects them). `goal_flag` calls `body.win()`; `checkpoint` calls `GameManager.set_checkpoint()` + emits `Events.checkpoint_activated`; `fruit` increments `GameManager.score`. `goal_flag`/`checkpoint`/`fruit` are on the `interactable` layer, mask `player`, still use `body_entered`.

**Touch controls (`ui/touch_controls/`)** — a `CanvasLayer` of `TouchScreenButton`s (left/right/jump/attack/dash/interact/pause) whose `action` maps to the same InputMap actions as the keyboard, so `player.gd` needs no touch-specific code. `level_base.gd` instances it per level and connects its `pause_pressed` signal. Visibility: `SaveManager.get_setting("touch_controls")` — "auto" shows it only when `DisplayServer.is_touchscreen_available()`. `project.godot` has `emulate_touch_from_mouse` on so the buttons work with a mouse for desktop testing (set the setting to "on" to see them there).

**Worlds & Hub** — `WorldData` (`core/world_data.gd`, `class_name`, no autoload) groups levels into 3 worlds via the `WORLDS` array (`id` / `name` / ordered `levels` / `unlock_boss` / `unlock_level`) — the single source of truth for world order + unlock chain. `forest` (`level_1,level_2`, open) → `castle` (`level_3,level_4,boss_forest`, opens when `level_2` is in `completed_levels`) → `dungeon` (`level_5,level_6`, opens when boss `forest_boss` is defeated). `is_world_unlocked()` requires BOTH `unlock_boss` (in `SaveManager.defeated_bosses`) and `unlock_level` (`SaveManager.is_level_completed`) to pass; `""` skips that check. Helpers: `first_level()`, `next_in_world()` (`""` when the given level is the world's last), `world_of()`. `level_base.gd` shows a fading title card on `_ready` when `world_title`/`level_subtitle` are set on the level root. The **hub** (`levels/hub/hub.tscn`, `hub.gd extends LevelBase`, no enemies/flag/checkpoint) is a walkable room with one `objects/portal/` per world (stand in it + `interact` → first level of that world, greyed + 🔒 if locked; plays the player's `door_in` anim if the character has one — King does, Captain fades), `objects/hub_sign/` signposts (`interact` → an arbitrary `target_scene`, currently the Levels menu), and `objects/npc/` (`Area2D` + `interact` → `Dialogue.open()` with up to `line_1..3` + optional `report_abilities` line built from `SaveManager.unlocked_abilities`; reuses the Pig `SpriteFrames`, pops a Kings-and-Pigs "Hello" bubble while talking). Flow within a world is a **chain**: `end_screen`'s "Next Level" button (shown only when `won and WorldData.next_in_world(current_level_id) != ""`) jumps straight to the next level; you only return to the hub after the world's boss (or via the "Hub" button / pause menu). `GameManager.current_world` is set by the portal on entry.

**Flow:** `main_menu` (re-applies saved fullscreen; **Continue** → hub, restoring the saved `character` setting) → `character_select` (sets `GameManager.selected_character`, persists it via `SaveManager.set_setting("character", …)`) → `hub` → portal → world level chain (`level` → `end_screen` → "Next Level" → next `level` → … → boss) → `end_screen` (records result; "Next Level" / "Retry" / "Hub"). `level_select` (reached from a hub signpost) is the manual per-level entry and also returns to the hub.

## Conventions (from CONTRIBUTING.md)

- `snake_case` files/folders, `PascalCase` scene node names, `SCREAMING_SNAKE_CASE` constants. Explicit GDScript types everywhere (`var x: float`, `-> void`). Comments explain **why**, not what.
- **Never build `SpriteFrames`/`AtlasTexture` in code at runtime.** Every `AnimatedSprite2D` uses a pre-baked `.tres` `SpriteFrames` file edited via Godot's SpriteFrames panel. Scenes bake a default set so the editor shows no config warning; code only `load()`s and assigns a different `.tres`.
- Object variants that differ only by texture/animation (fruit types, etc.) get **one** base scene + one `SpriteFrames` `.tres` per variant. Set the variant via an exported `SpriteFrames` property **on the instance node** (e.g. `variant_frames` on `fruit.gd`, which is `@tool` + has a setter for live editor preview). Never override properties of deeply-nested child nodes inside an instance — Godot may silently drop them on save.
- Don't commit `.godot/` (gitignored editor cache) or junk (`.DS_Store`). Check `git status` before `git add`.
- **Never put `#`/`##` comments inside a `.tscn`/`.tres`** — that's GDScript syntax; in Godot resource files the parser silently drops the node/section it lands in (a `##` inside a `[node]` block once made a whole `StaticBody2D` vanish → player fell through the floor). Use `;` for resource-file comments, or keep the explanation in the attached `.gd` / here.
