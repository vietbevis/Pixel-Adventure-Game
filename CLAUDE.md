# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A 2D platformer built with **Godot Engine 4.7** (Standard build — no C#/.NET), using the Pixel Adventure 1 art pack. Player picks a character, dodges hazards (spikes, saws, patrolling enemies), collects fruit, hits checkpoints, reaches the goal flag. UI, README and CONTRIBUTING are written in Vietnamese.

## Project layout gotcha

The Godot project root is **`Pixel-Adventure/`** (it used to be `game/`; older docs and memories still say `game/`). Import `Pixel-Adventure/project.godot`. The repo root holds only docs plus loose asset archives (`*.zip`, `*.rar`, extracted pack folders like `adve/`, `Kings and Pigs/`, `Sunny-land/`, `GothicVania Cemetery/`) that are raw source art, not wired into the project — leave them alone unless a task is about importing new assets.

## Running / testing

- No CLI build. Open `Pixel-Adventure/project.godot` in the Godot 4.7 editor and press F5. Main scene is `res://ui/splash/splash.tscn` (→ main menu).
- Godot 4.7.2 is at `/Applications/Godot.app/Contents/MacOS/Godot` (not on PATH). Headless import / scripts work; screenshots need a window. Gitignored dev harnesses in the project root: `_dev_overview.tscn` (whole-level PNG with tile grid), `_dev_camshots.tscn` (real gameplay frames at given positions), `_dev_playtest.tscn` (scripted gameplay checks: stomp, contact damage, dash wall, crusher, every enemy, both bosses, corner correction — prints PASS/FAIL), `_dev_shot.tscn` (single UI scene).
- After any folder-structure change, CONTRIBUTING requires opening the project in the editor once so it rescans and re-saves scenes flagged dirty.

## Architecture

**Feature-based folders, not type-based.** Each feature folder (`player/`, `levels/level_N/`, `objects/<thing>/`, `ui/<screen>/`) contains its own `.tscn` + `.gd` + `sprites/`. Only put an asset in `shared/` or `ui/shared/` if ≥2 features actually reference it (grep the path in `*.tscn`/`*.gd` to confirm).

**Autoloads (`core/`, registered in `project.godot [autoload]`):**
- `Events` (`events.gd`) — global signal-bus autoload: **signals only, no state or logic**. Gameplay `emit`s; HUD / SaveManager / achievements `connect`. Keeps gameplay decoupled from UI/Save. Not yet wired (skeleton from ROADMAP Phase 0).
- `GameManager` (`game_manager.gd`) — **pure runtime** state that survives scene changes: `selected_character`, `current_level_id`, `score`, `respawn_position`/`has_checkpoint`, `last_result` (`"win"`/`"lose"`), `_elapsed` playtime (paused-aware). `start_new_run()` resets it + calls `SaveManager.set_last_level()`. Hearts live in the player's `HealthComponent`; HUD reads them via `Events.player_health_changed`.
- `SceneTransition` (`scene_transition.tscn`) — **always** change scenes via `SceneTransition.goto(path)`. It unpauses, plays the fade animation, swaps the scene, never leaves the tree paused.
- `SaveManager` (`save_manager.gd`) — persists `completed_levels`, `high_scores`, `best_times`, `settings`, `unlocked_abilities`, `defeated_bosses`, `collected_secrets`, `max_hp_bonus`, `last_level` to `user://save_data.json` as JSON (every load is `.get(key, default)` for forward/backward compat). `is_level_unlocked()` gates level N on N-1. `record_result()` from the end screen. `get_setting`/`set_setting` for prefs. `is_ability_unlocked`/`unlock_ability`/`get_unlocked_abilities`, `is_boss_defeated`/`mark_boss_defeated`, `is_secret_collected`/`collect_secret`, `get_max_hp_bonus`/`add_max_hp_bonus`, `get_continue_level`/`set_last_level` — gameplay/UI query only through these, never the file.

**`AbilityGate`** (`objects/ability_gate/`) — `StaticBody2D` on the `world` layer that blocks passage until `SaveManager.is_ability_unlocked(required_ability)` (checked on `_ready` + `Events.ability_unlocked`); opens permanently. The metroidvania primitive. **`objects/secret_alcove/`** bundles one (`required_ability="dash"`) mid-way across a small floating `StaticBody2D` platform — you can land on the near half without dash but the gate walls off the far half where a **`objects/collectible_diamond/`** sits. Diamonds (`@tool` Area2D like `fruit.gd` but persistent — `@export secret_id`, `queue_free`s on `_ready` if `SaveManager.is_secret_collected`, else on pickup calls `collect_secret` + emits `Events.collectible_collected(id, "diamond")`) are placed under a `Secrets` node in each Forest level (`diamond_forest_1..3`). Collect all 3 → heart container (see `Progression`).
- `Progression` (`progression.gd`) — progression rules autoload: on `Events.boss_defeated` it `SaveManager.mark_boss_defeated()` and, if `BOSS_REWARDS` has the boss, `unlock_ability()` + emits `Events.ability_unlocked`. On `Events.collectible_collected` for a `"diamond"`, once all of `FOREST_SECRETS` (the 3 forest diamond ids) are in `collected_secrets` and no bonus yet, `SaveManager.add_max_hp_bonus(1)` + emits `Events.max_hp_increased(new_max)`. Also owns **`next_objective()`** — the ordered `OBJECTIVES` chain (forest → castle → dungeon → done) derived from save state; the hub Advisor NPC and the Progress screen both read it so they can never disagree. Note `BOSS_REWARDS` is empty: dash comes from `objects/ability_relic/` at the end of `level_2`, not from a boss.
- `Toast` (`toast.tscn`) — autoload CanvasLayer; on `Events.ability_unlocked` (etc.) slides a short message in at top-center. Survives scene changes.
- `Dialogue` (`ui/dialogue/dialogue.tscn`) — autoload CanvasLayer; `Dialogue.open(lines: PackedStringArray, speaker := "")` shows a bottom text panel, `interact`/`jump` advances a line, `set_input_as_handled()` so the same press doesn't leak to the player/portal. `is_open` flag (every `interact`-polling node — portal, hub_sign, npc — must gate on it) stays true one extra frame after the closing press. Not modal (no `get_tree().paused`). Emits `finished`.

**Non-autoload global classes (`class_name`):**
- `LevelData` (`core/levels.gd`) — the ordered `LEVELS` array (id / name / scene path) is the single source of truth for level order and the linear unlock chain (`SaveManager.is_level_unlocked` gates level N on N‑1). Order **matches `WorldData.WORLDS`**: `level_1, level_2` (forest), `level_3, level_4, boss_forest` (castle), `level_5, level_6, boss_dungeon` (dungeon) — so the two never disagree. Add a level = add one entry here + update `WorldData.WORLDS`. Also holds `format_time()`.
- `CharacterData` (`core/characters.gd`) — playable roster: `NAMES` (order shown in `character_select`) + `CHARACTERS` dict (display name, per-character `sprite.offset` to align feet to the shared collision box) + path helpers for `<name>_frames.tres` / `portrait.png` in `player/sprites/<Name>/`. Roster is King + Captain (Pixel Frog CC0, have attack anims); the 4 old froggy chars (`player/sprites/Ninja Frog/` etc.) are retired from `NAMES` but their folders stay for future skins. `character_select` builds its buttons from `NAMES` in code (like `level_select`).

**Reusable components (`components/`, `class_name`)** — 1 job per node, attached in the scene, wired via `@export`. `HealthComponent` (Node) — hp + i-frames; pure logic, emits `died`/`health_changed`/`invincibility_started`; owner forwards to `Events`. `Hitbox` (Area2D) — deals damage, passive data holder (`damage`, `knockback_force`), `enable()`/`disable()` per attack frame. `Hurtbox` (Area2D) — receives damage, active: on `area_entered` reads `damage` from a `Hitbox` (or 1 from a plain hazard Area2D on its mask layer) → `health_component.damage()`, emits `hurt(source)`. `EnemyHitReaction` (Node) — drop next to a `HealthComponent`; flashes the sprite white on `damaged`, and on `died` freezes the enemy, disables its shapes, emits `Events.enemy_died`, plays a pop tween, then `queue_free`s. All four auto-find a sibling `HealthComponent`/`AnimatedSprite2D` if the `@export` is unset. See CONTRIBUTING.md for the collision-layer table.

**Player (`player/player.gd`)** — `CharacterBody2D`, in group `"player"`. Hand-rolled movement: gravity, double jump (`MAX_JUMPS`), wall slide + wall jump. Infinite wall-climb is blocked two ways: a short post-jump horizontal input lock (`WALL_JUMP_LOCK_DURATION`), plus `last_wall_jump_dir` — you can't wall-jump the same wall face twice until you touch the floor or the opposite wall (zig-zag between two walls still works). Health lives in a `HealthComponent` child (`$HealthComponent`, `max_hp` 3, + `SaveManager.get_max_hp_bonus()` from heart containers applied in `_ready`; also listens to `Events.max_hp_increased` to bump live); `player.gd` connects its signals — `hit(force_reposition)` calls `health.damage(1)`, `died` → `_on_health_died` (respawn at checkpoint if any, else end screen), `health_changed` → mirrors `GameManager.hearts` + emits `Events.player_health_changed`. Player also listens to `Events.checkpoint_activated` to heal to full. `win()` sets result and transitions. Player scene has a `Hurtbox` child (mask `enemy_hitbox`) — `player.gd` connects `hurtbox.hurt` → `_on_hurt` (plays "hit"); damage is applied by the Hurtbox itself. Attack: `attack` action → `_start_attack()` places the `Hitbox` child in front by `facing` × `CharacterData.get_attack_reach()`, plays the `"attack"` anim; `sprite.frame_changed` enables the Hitbox from frame 1, `animation_finished` disables it and clears `is_attacking`. `hitbox.hit_landed` → brief `Engine.time_scale` hit-stop (`SceneTransition.goto` resets `time_scale` as a safety net). **Dash** — `dash` action, gated by `$AbilitySystem` (`ability_system.gd`, `is_unlocked("dash")` via `SaveManager`, `dev_unlock_all` export for testing); when `is_dashing`, `_physics_process` sets a flat horizontal velocity, skips gravity, and returns early. Cancelled by `_end_attack()` (called on hurt/death/respawn). Spawns `objects/fx/dust.tscn`. Only Dash goes through `AbilitySystem`; double/wall jump stay inline.

**Level builder (`tools/level_builder/`) — levels are GENERATED, never hand-edit their `.tscn`.** Workflow mirrors the temple-run project: build the node tree in pure GDScript, pack it, save `.tscn`.
- `levels/<id>.gd` — one spec per scene (`level_1..6`, `boss_forest`, `boss_dungeon`, `hub`), `extends "res://tools/level_builder/level_kit.gd"`. Draw with `chunks` (horizontal, bottom-aligned ASCII) or `canvas(w,h)` + `rect/at/text/put/back` (coords `(x, b)` with **b counted from the bottom**). Legend chars are documented at the top of `level_kit.gd`; per-world decoration chars (`j l q r u y z`) map to `shared/props/<world>/`. `backdrop = "<set>"` overrides the world's parallax.
- `level_kit.gd` autotiles, anchors every object from its **measured** footprint (sprite opaque rect / body collider — no hand offsets), sets camera limits + `fall_death_y`, and **refuses to write the scene** on: floating objects, missing start/goal, unknown chars, and **tight spots** — a standing cell with < 3 empty rows above (except `allow_low()` regions), a vertical gap < 3 cells wide, or a floating ledge edge diagonally within 1–2 cols / 1–3 rows of a standing edge (head-bonk corner). The player collider is 22×32, so 2-cell gaps "fit" on paper but jam in play.
- Run: `Godot --headless --path . -s res://tools/level_builder/build_levels.gd -- [ids] --json=<dir>`, then `python3 tools/level_builder/validate_levels.py <dir> [--margin=5]` — simulates player physics (double jump, wall jump, dash, trampolines, fans, one-way planks, ability gates, dash walls) and proves S → every checkpoint → goal; `--margin=N` inflates the body to expose pixel-perfect paths. A level with a mid-level relic passes if the relic is reachable without dash and the goal with it.
- `tile_forge.gd` (2 passes: `-- png`, `--import`, `-- tres`) makes `levels/shared/tilesets/{forest,castle,dungeon}_auto.png/.tres`: 16px atlases composed from 8px mini-tiles of a 9-slice source (PA grass, Kings&Pigs 32px bricks without downscaling, PA stone) — rows 0–3 solid by 4-neighbour mask × parity, row 4 one-way planks, row 5 non-colliding back wall. `build_objects.gd` generates the new enemy/trap scenes + their `SpriteFrames .tres`; `build_backgrounds.gd` generates the parallax scenes. See `levels/shared/tilesets/INVENTORY.md`.

**World themes** — tilesets as above (all 16px). Backdrops are multi-layer **`Parallax2D`** scenes built by `build_backgrounds.gd`: each layer its own `Parallax2D` (horizontal repeat, `scroll_scale.y` ≈ 0 so tall levels never scroll past the art) plus a screen-locked `Backstop` colour fill; sets `meadow` (forest/hub), `deep_forest` (level_2), `night_town` (level_3), `castle_hall` (castle interiors), `dark_castle` (dungeon). Menus use flattened panoramas from `shared/backgrounds/menu/`. Camera: zoom 1.7, `offset (0,-40)`; `CameraShake` adds to that base offset.

**Levels** — all six level scenes, both boss arenas and the hub share `levels/level_base.gd` (`class_name LevelBase`; arenas and hub `extends LevelBase` with a thin override). It sets the spawn point from `$Interactables/StartMarker` in `_enter_tree()` (before children `_ready()`), applies exported camera limits, detects falling off the map (`fall_death_y`), and owns the pause menu. Generated scene tree: `Parallax`, optional `BackWall`, `Decor` (drawn under terrain), `Terrain`, `Secrets`, `Traps`, `Interactables`, `Village` (hub portals + NPCs — must be siblings, the Advisor scans siblings for `world_id`), `Fruits`, `Enemies`, `Boss`, `Player`, `HUD`. Each level teaches one idea then tests it: L1 tutorial; L2 vertical climb (wall jump, fans, falling planks) ending with the Dash relic + a dash-wall corridor; L3 moat raft, dash-broken gate, crushers, ramparts, watchtower; L4 fire wave corridor, moving platforms over spikes, cannon room, spiked-ball hallway; L5 descent (graves, falling spikes, ghosts); L6 gauntlet (hellhounds, rail saws, fire pyramid, collapsing platforms over a void).

**Boss** — `BossBase` (`objects/bosses/boss_base.gd`, `class_name`, `CharacterBody2D`, groups `"enemy"`+`"boss"`): its own FSM (`INTRO`/`THINK`/`ATTACK`/`RECOVER`/`HURT`/`DEAD`), no coroutines — patterns are timer/step driven. Reuses `HealthComponent`/`Hurtbox`/`Hitbox` + `EnemyStats`; forwards HP → `Events.boss_health_changed`, phase → `Events.boss_phase_changed`, death → `Events.boss_defeated(boss_id)`, and its `@export display_name` → `Events.boss_intro(boss_id, display_name)` so `ui/boss_health_bar/` labels the right boss (the label used to be hardcoded "KING PIG", so the Warden fight showed the wrong name). `boss_intro` and the initial `boss_health_changed` are emitted **deferred** — in both arena scenes the boss node sits before `BossHealthBar`, so an immediate emit fires before the bar has connected. **King Pig** (`objects/bosses/king_pig/king_pig.tscn`, hp 18; `BossBase` has 1.6s stagger immunity so hit-spam cannot stun-lock it) — patterns unlock by phase (`_check_phase` at ≤66% / ≤33% hp): `bomb_toss` always (spawns an `objects/bomb/bomb.tscn` `Bomb` that arcs to the player, flight time scaled by distance, only the explosion hurts); `charge` from phase 2 (telegraph → dash, `Hitbox` on, long stun on wall hit); `jump_slam` from phase 3 (`SlamHitbox` = wide flat shockwave on landing). Phase change = roar + ~1s i-frame. `BodyHitbox` = always-on contact damage. `arena_bounds` (set on the instance) clamps the boss inside the room during charge. Arena `levels/boss_forest/boss_forest.tscn` (`boss_arena.gd extends LevelBase`, no goal flag — win on `boss_defeated`; `objects/boss_gate/` closes it, opens on defeat); registered as `boss_forest` in `LevelData`, unlocked after level 5. `ui/boss_health_bar/` listens to the `Events` boss signals. **Final boss — Ghost Warden** (`objects/bosses/ghost_warden/`, `boss_id` `dungeon_boss`, hp 16): a flying boss NOT on `BossBase` but emitting the same `Events.boss_*` signals. Patterns: `swoop` (telegraph, diagonal dive, hangs low = the opening), `summon` (2 skeletons), `rain` (phase 2+, soul orbs with floor warnings), `blink` (phase 3, reappears behind the player and swipes). Its `arena` Rect2 is set by `boss_dungeon.gd` spec. The old purple-tinted King Pig "Warden" is gone.

**Enemies** — `EnemyBase` (`objects/enemies/enemy_base.gd`, FSM `PATROL`/`IDLE`/`CHASE`/`ATTACK`/`RETURN`/`HURT`, `EnemyStats` resource) drives the castle **Pigs** (`pig`, `pig_ambusher`, `pig_bomber`). `Critter` (`objects/enemies/critter/critter.gd`, contact damage, `mode` = `WALK`/`HOP`/`RISE`/`CHARGE`) drives **Opossum** + **Frog** (forest) and **Skeleton** (hidden until you approach, then rises and chases) + **Hellhound** (charges when you are level with it) (dungeon). `FlyingEnemy` (`objects/enemies/flying/flying_enemy.gd`, `kind` = `SWOOP`/`HAUNT`) drives **Eagle** (dives at you from above) and **Ghost** (floats through walls, periodically fades — intangible while faded). Every ground enemy has a `StompBox` (`components/stomp_box.gd`): landing on its head damages it and calls `player.bounce()`. Enemy scenes built by `build_objects.gd` have their origin at the feet.

**Traps & interactables (`objects/`)** — `spikes`/`saw`/`orbit_saw`/`falling_spike`/`fire_trap`/`spiked_ball`/`crusher` are `Area2D` hazards on the `enemy_hitbox` layer (the player's `Hurtbox` detects them). `crusher` (Rock Head) falls when you are under it, raycasting each frame for the floor, then winches back up. `dash_wall` is a `StaticBody2D` that only breaks when the player touches it while `is_dashing` — the real "needs Dash" gate (unlike `ability_gate`, which just disappears once Dash is owned). `trampoline`, `fan`, `falling_platform`, `moving_platform`, `arrow_shooter`, `cannon` as named. `goal_flag` calls `body.win()`; `checkpoint` calls `GameManager.set_checkpoint()` + emits `Events.checkpoint_activated`; `fruit` increments `GameManager.score`. Player has **corner correction** (`_correct_corner`, ≤6px sideways nudge when a jump clips a ledge corner).

**Touch controls (`ui/touch_controls/`)** — a `CanvasLayer` of `TouchScreenButton`s (left/right/jump/attack/dash/interact/pause) whose `action` maps to the same InputMap actions as the keyboard, so `player.gd` needs no touch-specific code. `level_base.gd` instances it per level and connects its `pause_pressed` signal. Visibility: `SaveManager.get_setting("touch_controls")` — "auto" shows it only when `DisplayServer.is_touchscreen_available()`. `ui/settings_menu/` sets that mode, fullscreen, and volume; the **volume control is a 10-block bar with −/+ buttons**, not an `HSlider` — the old slider stretched a 55×15px 9-patch into a torn bar with the grabber floating off the track and no fill, so you could not see the level. Blocks are built in code like `hud.gd`'s hearts; clicking or dragging across them jumps to that step. `AudioManager` splits `apply_master_volume()` (bus only) from `set_master_volume()` (bus + save) so dragging does not call `SaveManager.set_setting`, which writes the file on every call. `project.godot` has `emulate_touch_from_mouse` on so the buttons work with a mouse for desktop testing (set the setting to "on" to see them there).

**Worlds & Hub** — `WorldData` (`core/world_data.gd`, `class_name`, no autoload) groups levels into 3 worlds via the `WORLDS` array (`id` / `name` / ordered `levels` / `unlock_boss` / `unlock_level`) — the single source of truth for world order + unlock chain. `forest` (`level_1,level_2`, open) → `castle` (`level_3,level_4,boss_forest`, opens when `level_2` is in `completed_levels`) → `dungeon` (`level_5,level_6`, opens when boss `forest_boss` is defeated). `is_world_unlocked()` requires BOTH `unlock_boss` (in `SaveManager.defeated_bosses`) and `unlock_level` (`SaveManager.is_level_completed`) to pass; `""` skips that check. Helpers: `first_level()`, `next_in_world()` (`""` when the given level is the world's last), `world_of()`. `level_base.gd` shows a fading title card on `_ready` when `world_title`/`level_subtitle` are set on the level root. The **hub** (`levels/hub/hub.tscn`, `hub.gd extends LevelBase`, no enemies/flag/checkpoint) is a walkable room with one `objects/portal/` per world (stand in it + `interact` → first level of that world, greyed + 🔒 if locked; plays the player's `door_in` anim if the character has one — King does, Captain fades), `objects/hub_sign/` signposts (`interact` → an arbitrary `target_scene`, currently the Levels menu), and `objects/npc/` (`Area2D` + `interact` → `Dialogue.open()`; reuses the Pig `SpriteFrames`, pops a Kings-and-Pigs "Hello" bubble while talking). **NPCs have AI**: `npc.gd` is a hand-rolled FSM like `EnemyBase`, with `@export behavior` = `STATIONARY` (Cố vấn — stands still, every ~3.5s turns to face the portal of the current objective world, found by scanning siblings for a `world_id` property) / `WANDER` (Dân làng — patrols `wander_range`, pauses for chores, follows the player at `follow_distance` when near, returns when they leave; a 3-tier mood read from save progress scales walk speed, tint and dialogue) / `SKITTISH` (Heo đào ngũ — flees when the player enters `flee_radius` while attacking, dashing or running faster than `THREAT_SPEED`; refuses to talk while scared, prompt reads "Đứng yên...", calms after the player holds still for `calm_time`). Movement is `global_position.x` only (flat hub floor, no physics), fenced by `wander_range + leash_extra` so an NPC never wanders into a portal's `interact` zone. Dialogue = `line_1..3` + optional `report_abilities` line + one `@export dynamic_line` (`NEXT_OBJECTIVE` / `MOOD` / `WORLD_TIP`). Flow within a world is a **chain**: `end_screen`'s "Next Level" button (shown only when `won and WorldData.next_in_world(current_level_id) != ""`) jumps straight to the next level; you only return to the hub after the world's boss (or via the "Hub" button / pause menu). `GameManager.current_world` is set by the portal on entry.

**Result feedback & end screen** — losing the last heart with no checkpoint, or touching the goal flag, plays an in-level **`ui/result_flash/`** (CanvasLayer 60: full-screen veil + big label, `"lose"`/`"win"`/`"final"`) plus `AudioManager.play_sting()` (`game_over`/`victory`/`final_victory`, `.wav` — no ogg encoder on this machine; `.import` sidecars are committed) before `player.gd` transitions to `end_screen` 1.2–2.0s later. `player.gd` owns this rather than an `Events.player_died` listener, because that signal also fires on a checkpoint respawn; `win()` disables `hurtbox.monitoring` for the wait so a hazard cannot flip a win into a loss. `end_screen` always shows **4 buttons** in a 2-column `ButtonsGrid` (Chơi lại / Về Làng / Trang chủ / Tiến trình) with `NextButton` as a conditional 5th above it, and adds a whole-run summary when `current_level_id == "boss_dungeon"` (winning there = beating the game). **`ui/progress_screen/`** renders everything in `SaveManager` — win objective + next step, per-world level rows with best score/time, abilities, bosses, secrets, and the 6 achievements (the only UI achievements have); reached from end_screen and main menu, returning via `GameManager.progress_return_scene`. `GameManager.result_recorded` stops `record_result` from running twice when you bounce to the Progress screen and back.

**Flow:** `main_menu` (re-applies saved fullscreen, starts hub music; **Continue** → hub, restoring the saved `character` setting) → `character_select` (sets `GameManager.selected_character`, persists it via `SaveManager.set_setting("character", …)`) → `hub` → portal → world level chain (`level` → `end_screen` → "Next Level" → next `level` → … → boss) → `end_screen` (records result; "Next Level" / "Retry" / "Hub"). `level_select` (reached from a hub signpost) is the manual per-level entry and also returns to the hub.

## Conventions (from CONTRIBUTING.md)

- `snake_case` files/folders, `PascalCase` scene node names, `SCREAMING_SNAKE_CASE` constants. Explicit GDScript types everywhere (`var x: float`, `-> void`). Comments explain **why**, not what.
- **All player-facing text is Vietnamese, hardcoded — there is no i18n layer.** That covers `.tscn` `text =` properties, strings built in `.gd`, level names in `LevelData`, character display names in `CharacterData`, achievement titles, toasts and NPC dialogue. Identifiers stay English (`CharacterData.NAMES` is still `["King", "Captain"]` because they index sprite folders and the save file — only the `display` field is translated). When adding UI, write Vietnamese directly; the Handjet font has full Vietnamese coverage (verified against its cmap).
- **Never build `SpriteFrames`/`AtlasTexture` in code at runtime.** Every `AnimatedSprite2D` uses a pre-baked `.tres` `SpriteFrames` file edited via Godot's SpriteFrames panel. Scenes bake a default set so the editor shows no config warning; code only `load()`s and assigns a different `.tres`.
- Object variants that differ only by texture/animation (fruit types, etc.) get **one** base scene + one `SpriteFrames` `.tres` per variant. Set the variant via an exported `SpriteFrames` property **on the instance node** (e.g. `variant_frames` on `fruit.gd`, which is `@tool` + has a setter for live editor preview). Never override properties of deeply-nested child nodes inside an instance — Godot may silently drop them on save.
- Don't commit `.godot/` (gitignored editor cache) or junk (`.DS_Store`). Check `git status` before `git add`.
- **Never put `#`/`##` comments inside a `.tscn`/`.tres`** — that's GDScript syntax; in Godot resource files the parser silently drops the node/section it lands in (a `##` inside a `[node]` block once made a whole `StaticBody2D` vanish → player fell through the floor). Use `;` for resource-file comments, or keep the explanation in the attached `.gd` / here.

## PLAN.md / ROADMAP.md

`PLAN.md` (Vietnamese, repo root) is the **current** plan document: an audit of the project against the coursework requirements (game-over state, ≥3 levels with saved progress, win state, ≥3 smart NPCs), plus the spec and implementation notes for what was added to close the gaps.

`ROADMAP.md` is the older metroidvania expansion plan (P0–P11). Much of it is **stale** — it still describes systems as missing that have since been built. Read it for background; trust `PLAN.md` where they disagree.
